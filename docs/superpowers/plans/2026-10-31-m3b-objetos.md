# M3b — objetos sólidos e presença por modo: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** o Jake fica de pé sobre e é barrado pelos objetos sólidos; a cena mostra só os
objetos do modo solo e o Jake é o objeto de início do jogador.

**Architecture:** o parser expõe a máscara de modos; `scene.rs` decide presença, jogador e
quais objetos são sólidos para o Jake (regras puras em `objects.rs`, novo) e entrega as caixas
ao `World` junto com as das células.

**Tech Stack:** Rust 2024 (MSRV 1.85: sem let chains), crates do workspace.

**Spec:** `docs/superpowers/specs/2026-10-31-m3b-objetos-design.md`

## Global Constraints

- GPL-3.0-or-later, cabeçalho SPDX em arquivo novo; comentários e docs em português.
- Nada de dados do jogo nem desmontagem no repositório.
- `/home/claude/check.sh` verde (fmt, clippy -D warnings, testes com dados reais) antes de
  cada commit.

## Review Focus

1. Objeto sólido sem BRD (`names[1]` vazio ou ausente) → não colide, sem aviso fatal.
2. Jake nascendo já sobreposto a um objeto sólido → não fica preso (o fuzz verifica que não
   termina dentro de sólido; o teste da T_J_007 cobre o caso real).
3. Fase de vários jogadores (`C_*`, `M_*`) → sem filtro, Jake como na M3a (teste em Task 2).
4. Objeto de versão < 1010 → modos 0xfe (teste em Task 1).
5. Objeto com animação ausente mas sólido → colide mesmo assim (as caixas vêm do BRD).
